# tools/nup

| Script | What it does | Usage |
|---|---|---|
| `extract.py` | A .nup package (a55uka/nup format v1, the single-file dumps of emulators and dump sites: base, updates and add-ons, files raw or zstd, deduplicated by sha256) into `exefs/` + `romfs/` in the destination. The program is the highest update, else the base; an update shadows the base's files by path, and a standalone update (no base in the container, flag bit 0) is the whole game. Fail-closed validation per the spec (the TOC's sha256 before any TOC value is trusted, bounds, 16-byte extents, the standalone rule, names as labels never paths); every file through `<name>.part`, renamed only when size and sha256 match; an existing file with the right size is skipped (resume), a file whose sha256 was already written in the run is copied from that file; a free-space check before starting. One `progress <done> <total>` line per 500 files on stdout (prepare.py passes such lines to the start screen), the rest on stderr | `uv run tools/nup/extract.py NUP [--out DIR] [--list] [--only exefs\|romfs] [--package N] [--no-verify] [--rehash] [--jobs N]`; `--out` defaults to the game folder (`game/`, or `MKW_GAME=DIR`). The files run in parallel (`--jobs`, default 8): a destination is usually a NAS where one create+rename is ~40 ms while the bytes are cheap, so the per-file metadata latency is the limit and overlaps across threads |
