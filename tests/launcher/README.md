# tests/launcher

The setup, the installation selector and the Add to Steam of the start screen.

| File | What it checks |
|---|---|
| `test_beside.py` | `beside.py`: a step's progress held until the main loop reaches it, and its error raised where it is joined |
| `test_nextsetup.py` | `prepare.py --next` (`nextsetup.py`): an update without shaders keeps the played `spirv/`, the state resumed from `setup-next/`, a finished update promoted and an unfinished or other version's removed |
| `test_setup.py` | The setup's free-space check before it copies (a short drive fails with code `space`, what a cut copy left not counted again), and its command lines and files from folders with spaces and accents: the compiler's path on its way to the shader step (issue #29), the resume without `--source` after an update (from the game folder when a copy's original files are gone, issue #501), the update's version order, its clean-up of `*.old` files, and release asset selection and CLI update downloads for both Linux AppImage architectures and Windows ZIPs (wrong sizes and checksums are rejected before staging with an error event), the update that regenerates the code cleanup removed, NVIDIA's downloads fetched again when they arrive damaged (issue #207), a broken SM86 spec built again instead of reused (issue #325), the warm step's `pipeline-pairs.bin` of another format written again (with `extract.py` first when its shaders are gone), and setup tools, unpacking and warm-up when the installation is separate from the launcher, including symlink/junction aliases of long installation paths and response-file paths with spaces, quotes and backslashes for Clang, Zig and lld-link |
| `test_game_fonts.py` | `tools/i18n/game_fonts.py`: the game's `.bfotf` fonts unwrapped and wrapped again (header with the font's size, XOR key at each offset, padding after the font ignored, a cut file refused) |
| `test_fastcc.py` | `tools/prepare/fastcc.py` with a stand-in zig and clang: zig's `-cc1` line run on clang with the chunk's input, output and name put in; zig when clang is another version or `MKW_SETUP_CC=zig` |
| `test_gamecode.py` | The compile step's answer to a compiler crash (`tools/prepare/gamecode.py`), with a fake compiler: a crash (ICE) tried once more with its first lines logged, a second crash or a plain source error reported, a plain error not retried (#506); `MKW_SETUP_CPU` (v3 by default, v2, anything else stops) |
| `test_steam.py` | The Tools page's Add to Steam (`tools/prepare/steam.py`): the binary `shortcuts.vdf` read back as it was written (strings, ints, a 64-bit field, tags), an entry with the same executable replaced instead of doubled with the other shortcuts kept whole, a missing file created, a pid file that is not there or is not a number reading as Steam closed, Gaming Mode's library images written in their sizes (from `--art` too), replacing only its own, the icon naming the drawn one, and a shortcut it added before under another program path replaced instead of doubled, a player's own kept |
| `test_mod_import_encoding.py` | The real mod-import CLI with cp1252 pipes: UTF-8 success, error paths, variants and argument diagnostics for ASCII, accented and Chinese names, from folders and synthetic ZIPs |
| `test_mod_import_events.py` | Actual importer output through the production Mods-page result parser: names with spaces and Unicode, metadata-free results and error messages, without SDL or a game |
| `test_save_backups.py` | Save ZIPs retain each snapshot across repeated and concurrent calls, sanitized-name collisions, stale partials and write failures; normal backup and missing-profile CLI results |
| `test_setup.py` | The setup's free-space check before it copies (a short drive fails with code `space`, what a cut copy left not counted again), and its command lines and files from folders with spaces and accents: the compiler's path on its way to the shader step (issue #29), the resume without `--source` after an update (from the game folder when a copy's original files are gone, issue #501), the update's version order, its clean-up of `*.old` files, and release asset selection and CLI update downloads for both Linux AppImage architectures and Windows ZIPs (wrong sizes and checksums are rejected before staging with an error event), the update that regenerates the code cleanup removed, NVIDIA's downloads fetched again when they arrive damaged (issue #207), a broken SM86 spec built again instead of reused (issue #325), and setup tools, unpacking and warm-up when the installation is separate from the launcher, including symlink/junction aliases of long installation paths and response-file paths with spaces, quotes and backslashes for Clang, Zig and lld-link |
| `test_gamecode.py` | The compile step's answer to a compiler crash (`tools/prepare/gamecode.py`), with a fake compiler: a crash (ICE) tried once more with its first lines logged, a second crash or a plain source error reported, a plain error not retried (#506) |
| `test_steam.py` | The Tools page's Add to Steam (`tools/prepare/steam.py`): the binary `shortcuts.vdf` read back as it was written (strings, ints, a 64-bit field, tags), an entry with the same executable replaced instead of doubled with the other shortcuts kept whole, a missing file created, a truncated file reported to the launcher and left intact, a pid file that is not there or is not a number reading as Steam closed, Gaming Mode's library images written in their sizes (from `--art` too), replacing only its own, the icon naming the drawn one, and a shortcut it added before under another program path replaced instead of doubled, a player's own kept |
| `test_finddumps.py` | The setup's search for the player's copies (`tools/prepare/finddumps.py`): a Mario Kart World `.nup` with its version from the package's table, another game's and an unknown version told apart, `.nx` and loose copies of a known build found, an unknown build, hidden folders, folders past the depth and the installation itself left out |
| `test_game_dir.py` | Installation selection and persistence, relative paths, UTF-8 length boundaries, trailing whitespace and quotes, environment overrides, settings saved in the chosen folder, library readiness before memory initialization, recovery from failed or invalid saved selections, and log-folder discovery with launcher fallbacks and active log destinations (`t_game_dir.c`, POSIX harness) |
| `test_game_dir_windows.py` | The actual Windows selector compiled with Clang/MinGW, run natively or under Wine: UTF-16 root limits with room for derived filenames, ASCII/BMP/supplementary characters, prepared DLL discovery, rejection before persistence, relative-prefix counting and recovery from invalid saved paths (`t_game_dir.c`; skipped when the toolchain or runner is absent) |
| `test_launcher_paths.py` | Setup completion refreshes the real boot/mod RomFS resolvers in the same session, preserving argv/environment precedence, dirty settings and held config pointers; synthetic NUP imports and SARC merges verify original hashes, source changes, relative/Windows paths, missing sources and repeated/failed setup (`t_launcher_paths.c`) |
| `probe_build.py` | Not a test: the build of the Windows MinGW probes for the two above, with a 30 s guard per attempt and up to three attempts (the wait for clang sometimes never returns on the 20261116 runner image; each hang goes to stderr) |

C sources the tests here build with the compiler at hand and run:

| File | Built by | What it checks |
|---|---|---|
| `t_game_dir.c` | `test_game_dir.py`, `test_game_dir_windows.py` | Settings, installation discovery and log-folder discovery with real files and single-thread platform stubs; Windows uses UTF-16 file APIs and UTF-8 conversion through `wmain`; no game, SDL or GPU |
| `t_launcher_paths.c` | `test_launcher_paths.py` | Real configuration plus the production boot/mod path and setup-completion functions, with file stubs and UTF-8 entry point cut from `t_game_dir.c`; driven over stdin without SDL, a game or GPU |
